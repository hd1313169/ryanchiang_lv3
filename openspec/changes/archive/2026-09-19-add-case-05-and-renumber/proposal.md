## Why

Case study numbers currently mirror homepage placement (01 is the top card), so a newly added case would either become 01 and force every other case to shift, or take a large number and sit at the bottom. The owner wants numbers to grow with newer cases (newest = largest) while the homepage still lists newest first, and a fifth case study (規格驅動 Prototype, AI 工作流) needs to be added under that scheme.

## What Changes

- Add case study **05** from `content/case05.md`, following the structure of the existing four case studies (frontmatter fields, 專案背景 → 設計挑戰 → 設計決策 → 設計成果 → 心得與反思, floating section nav, next-case link). No images yet, and no placeholder or annotation for them.
- Renumber the existing four by reversing them: 04→01 (Echorise), 03→02 (商業選址), 02→03 (證券業務分配), 01→04 (整合行銷). **BREAKING**: `/work/01` … `/work/04` now point to different case studies (no external links exist, so no redirects).
- Renumber all number-derived assets in step: `public/images/case-0X/` folders and `X-*` file names, `src/assets/photos/cover-0X(-dark)` files, in-content image paths, and the original source material under `content/img/case/`.
- Homepage lists cases in descending number (05 → 01), so visual order is unchanged for the existing four and the new case sits on top. The "下一篇案例" link follows the same order and wraps from 01 back to 05.
- Remove the `order` frontmatter field; ordering is derived from the case number so numbering and placement can no longer drift apart.
- Homepage: adapt the work grid to five cards (entrance stagger delay for the fifth card; the odd card in the two-column grid is allowed to leave an empty cell).
- Case 05 has no cover yet: its homepage card uses the existing gray placeholder until a cover is supplied.
